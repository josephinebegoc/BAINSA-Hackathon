Accessible Attention for Excel — Technical Overview

Static frontend and one Python serverless function on Vercel. No database, no build step, no framework.

Pipeline

An uploaded .xlsx is read by openpyxl twice — once for formulas, once for the values Excel last calculated — and becomes a SheetModel: every cell with its value and its visual vocabulary (fill, font colour, bold, italic, borders, comments, number format, errors). A deterministic engine annotates cells with cues; the browser holds the model and does all narration, so the server is stateless.

The attention engine is our own code, not a model

478 lines of pure functions, no I/O. Four cue types: author visual (fill, font colour, bold, or a column formatted unlike its neighbours), statistical (robust z-score on median/MAD), pattern (three or more consecutive moves reversed by over 25%) and functional (Excel errors). Two decisions were forced by real files:

  • Comparability by scale, not formatting. Real sheets are formatted inconsistently — our demo workbook has one revenue column set to percent and four left as General. Grouping by number format tore a twelve-month series into three. We group columns by the scale of their medians, so a mis-formatted revenue figure is still revenue-sized.
  • A minimum effect size on the z-score. A tightly-clustered series has a near-zero MAD, so the z-score explodes on noise — it flagged a cell 13% from its median. Distance-from-median alone fails the other way: a row that changes level partway through has both ends far from it.

Sonification

A row plays as tones. Pitch carries two things: the row's median fixes its register, so rows are comparable by ear, and the row's own range is expanded around it, so a row sitting low still has an audible shape. Frequency is exponential in value, so equal steps sound like equal intervals; amplitude falls ~3 dB per octave to offset equal-loudness curves, so only pitch changes and a low note never reads as faint.

The LLM is one component, not the product

Every spoken sentence has a deterministic template. The Anthropic API only rephrases, and its output is rejected if it contains a judgement word or a number not supplied in the input. The deployed demo runs with no API key — all detection and all wording is ours.

Accessibility and reproducibility

Two output modes: self-voicing via speechSynthesis, and a screen-reader mode writing to aria-live regions so VoiceOver and NVDA speak it. One earcon for all cue types, with the cue name spoken before the cell so a listener knows to attend before the content arrives. Grid at role="application"; markers carry letters as well as colour; Atkinson Hyperlegible throughout. 82 Python tests and 27 JavaScript assertions, including a regression test that the engine independently reproduces the shared fixture's cues, and tests that every failure path returns a speakable sentence.
