Accessible Attention for Excel — Technical Overview

A static frontend and one Python serverless function, deployed on Vercel.

Architecture

The frontend is a set of ES modules served as static files: app.js (grid, navigation, modes), voice.js (speech), cues.js (earcons and vibration) and sonify.js (tones). The backend is a single FastAPI function providing /api/health, /api/upload (multipart .xlsx), /api/explain and /api/overview. The browser holds the parsed workbook and passes the context each call needs, so every request is independent. Dependencies: FastAPI, openpyxl, python-multipart, anthropic.

Extraction

openpyxl opens the workbook twice: data_only=False yields formulas, data_only=True yields the values and error codes Excel last calculated. Each cell carries its value, formatted display, row label, column header, fill and font colour, bold, italic, underline, strikethrough, borders, comment, number format and error code. The header row is the first row that is mostly text, the label column the first mostly-text column below it, and the table extends to the first blank row. Theme and indexed colours are resolved to a name where possible and otherwise marked as present.

Attention engine

attention.py is 478 lines of pure functions that take cells and return cues.

CueRule
visualA solid fill, a red or orange font, bold against an unbolded row, or a column whose number format differs in kind from its series.
anomaly0.6745·|x−median|/MAD > 3.5 together with a distance of 15% or more from the median. Where MAD/|median| < 0.01, a distance above 40% is used. Series of four or more numbers qualify.
trendThree or more consecutive moves in one direction followed by a reversal above 25%.
errorA cached Excel error value.

Cells are compared within groups of columns holding the same kind of quantity. Columns join a group while the order of magnitude of their medians falls within 100× of each other, measured per column across the whole sheet. Groups of four or more columns are analysed. Cues carry a severity and are ordered by severity, then by reading order.

Sonification

sonify.js uses the Web Audio API. The sheet's main column group fixes one pitch scale, mapping its 5th to 95th percentile onto 110–1760 Hz and clamping values beyond it. Within that scale a row's median sets its register, and the row's own minimum to maximum is stretched across 34% of the range around that register. Frequency rises exponentially with value, so equal steps in the data produce equal musical intervals. Amplitude follows (110/f)0.5, about −3 dB per octave, matching equal-loudness curves so that perceived volume stays constant. Notes last 400 ms with a 70 ms gap and pan from left to right. Error cells sound a square wave at 110 Hz; empty cells are silent.

Spoken text

The engine's findings are rendered into sentences by templates in overview.py and explain.py. The Anthropic API then rephrases those sentences into natural speech within a 5 s timeout. Its output is checked against the input facts and accepted when it contains only supplied figures, plain prose and no evaluative language; the template is used otherwise.

Accessibility

Speech reaches the user by two paths: speechSynthesis, cancelled before each utterance so announcements track navigation, and aria-live regions (polite for movement, assertive for cues) read by VoiceOver and NVDA. The grid carries role="application" so arrow keys reach it in browse mode. A single earcon precedes speech on every flagged cell and the cue name is spoken first. navigator.vibrate is feature-detected. Cue markers carry a letter alongside their colour, and the interface is set in Atkinson Hyperlegible.

Tests

82 Python tests and 27 JavaScript assertions cover the cue rules, extraction, the API's failure paths and the pitch mapping, including a regression test that the engine reproduces the shared fixture's cues and ordering from the cells alone.
